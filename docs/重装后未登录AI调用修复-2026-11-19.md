# 重装后未登录仍可调用官方 AI

## 原因与修复

个人中心按 App Group 中的 `user.v1` 判断是否已登录，而原来的 `SharedStore.token()` 独立读取钥匙串凭据。清除本地数据后，若钥匙串中仍保留之前的有效 token，界面显示未登录，但官方模型路由仍能用旧 token 获取原账号的 VIP 配置并发起请求。此处是客户端登录状态不一致，并非服务端取消了 token 和 VIP 校验。

`SharedStore.token()` 现要求当前账号快照存在且 token 非空。缺少账号信息时，不再向任何官方接口提供残留 token；用户重新登录后才使用新会话。官方路由原有的 VIP 和功能配置检查保持不变；自配模型使用自己的 API Key，仍按原规则支持免登录。

依据：[Apple Developer Technical Support 对卸载后钥匙串持久性的说明](https://developer.apple.com/forums/thread/36442)。不能依赖卸载操作必然清除钥匙串数据。

## 验证

新增 `SessionConsistencyTests`，使用隔离的 UserDefaults 和内存凭据仓库模拟本地数据清除而钥匙串保留的边界，未读取或修改用户真实凭据。

- 修复前，账号为空但 `token()` 返回旧凭据，官方配置接口请求计数为 1，回归测试失败。
- 修复后，同一场景 `token()` 为 nil，官方接口请求计数为 0。
- 有效登录在普通重启后仍然生效；退出登录后，即使键盘尚未刷新用户界面，也不再提供凭据。
- 缺失或空凭据不作为有效会话使用。
- `RoutingTests` 同时验证官方 VIP 路由、过期会话拒绝及自配模型免登录调用。
- 核心测试 59 项全部通过，`/tmp/lianai-session-consistency-after.log`。

修改需通过新版安装生效。本轮没有卸载用户手机上的 App，也没有改变手机上的登录状态。
