# 触摸响应与候选刷新优化

日期：2026-11-04。对应反馈：“快了一点，但是打字还是不跟手、不流畅”。

上一轮处理了读音表、词典计算和整套按键重建；那次引擎调用计时不代表完整输入手感。本轮继续调整触摸到响应、候选更新和布局的路径。

## 修改

- 九宫格字母、全键盘字母、数字键盘数字与删除键在 `touchDown` 响应，不再等待 `touchUpInside`。一次落指只输入一次，松开不重复输入。
- 空格和回车保留松开输入及长按行为；候选和拼音筛选保留松开选中，横向滑动取消时不提前提交。普通字母键不再附加本项目的 0.42 秒长按识别器。无障碍激活仍可输入。
- 候选、拼音筛选和超会说草稿在结构不变时更新已有控件，复用按钮和约束；每次刷新会替换当前候选回调，防止选到旧候选。数量减少时清除隐藏按钮回调、停用其宽度约束。
- 关闭候选等横向滚动区的 `delaysContentTouches`，并通过 `touchesShouldCancel` 让滑动取消已落指的候选按钮，避免误选。保留原有 iOS 26+ 边缘模糊关闭逻辑。
- 键盘目标高度在内存中计算完后提交一次，最终高度相同则不修改约束。
- 英文大小写变化只更新字母标题，避免输入首字母或切换大小写时拆掉按键网格。

- 补查发现：拼音删到最后一位时，原代码只执行 `unmarkText`，把最后一个标记字母留在宿主输入框。删除后组合为空时，现在先用空串替换标记区，再取消标记；超会说内部草稿不操作宿主标记区。

没有增加产品功能、减少候选数量或调整词典排序，也没有关闭声音或触感设置。

## 真机进一步发现：同步按键音阻塞

在第一版触摸调整的真机 UI 测试期间，用 CPU Profiler 单独采样键盘扩展约 15.6 秒。Hangs（阈值 250 ms）记录了 13 次约 440–453 ms 的主线程 Microhang。对应时间窗口的调用栈进入 `KeyboardViewController.feedback → AVAudioPlayer.play → AudioQueueNewOutputWithAudioSession → AudioQueue XPC`，包含音频队列创建失败路径。

之前“提前 prepareToPlay”没有检查返回结果，失败后仍然每敲一个键再次同步播放。功能用例能通过，也不能证明没有这种卡顿。

新增 `KeyboardClickAudio`，音频对象创建、准备、设置音量和播放统一放在专用串行队列。输入线程只提交播放请求；超过 80 ms 的积压声音丢弃，准备/播放失败后该次键盘显示期间不再反复尝试。下一次键盘显示可重试，不修改用户音量或触感设置。音频服务不可用时不保证有声音，但不会继续阻塞输入。

新增故障注入测试：让音频准备被信号量阻塞，期间真实 `InputKey` 必须仍能落指输入；恢复后只播放新请求，不重放过时声音。

Apple 提供的键盘声音及完全访问说明见 [Custom Keyboard](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/CustomKeyboard.html)。本轮判断来源是上面的真机采样栈，未将文档中的能力说明当作性能测量。

失败与修正记录保留：

- `TouchResponseSimulator.xcresult` 最初的两项控件断言把 UIKit 自带识别器也算成项目长按识别器；改为只检查本项目 0.42 秒识别器后通过。
- `AudioResponseSimulator.xcresult` 的首次 AI 测试失败现场明确显示“剪贴板没有文字”。测试先切换系统设置，使模拟器测试剪贴板失效。辅助流程现于返回设置后重启 fixture 主 App，重新准备测试剪贴板，授权及生成流程重测通过；没有因此改变正式产品的授权或剪贴板逻辑。
- `TouchFinalSimulator.xcresult` 的滚动测试在候选仍不在可见区时直接检查 `isHittable`；设备上通过，但模拟器不能给出有效点击点。测试改为先断言滑动不提交，然后删空并重新组合再检查提交，避免依赖精确惯性停点。
- 上述追加流程在 `TouchFinalTypingSimulator.xcresult` 实际捕获了旧删除缺陷：宿主为 `o你好` 而非 `你好`。该失败没有算作通过，产品删除逻辑按本页描述修复后重新验证。
