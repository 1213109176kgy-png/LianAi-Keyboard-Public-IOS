# 真机底部占位与输入流畅度修复

后续针对“仍不跟手”的触摸及界面刷新调整，见[触摸响应与候选刷新优化](触摸响应与候选刷新优化.md)。本页保留上一轮测量与验收记录。

日期：2026-11-04。实测设备：iPhone 16 Pro Max，iOS 18.7.8；测试与安装均使用本机免费 Personal Team。

## 已修改

- 删除截图圈出的光标滑块、滑块手势及底部占位，减少对应键盘高度。末行按键下方只保留正常边距。
- 普通输入不再每次拆掉整套按键和 Auto Layout 约束。布局、主题、中英文状态相同时，保留按键网格，只刷新候选、拼音选择与草稿区域；切换布局或面板时才重新构建。
- 九宫格读音表在引擎初始化时加载，避免第一次按键才解析约 4.4 万行数据；重复读音查询按“候选文本 + 当前数字串”缓存，保留多音字上下文。
- 英文补全使用前缀和长度索引，减少每次扫描全部词典；保留原排序、学习权重、大小写、短语和单字母纠错。
- 触感对象复用，按键音提前准备。没有关闭用户的声音/触感设置，也没有减少原候选数量。

## 真机测量与边界

同一手机、Release、同一组 41 次合成九宫格按键调用：

| 项目 | 原版 | 修改后 |
| --- | ---: | ---: |
| 引擎/读音处理 P50 | 0.238 ms | 0.067 ms |
| 引擎/读音处理 P95 | 8.242 ms | 0.154 ms |
| 最大单次处理 | 88.326 ms | 0.178 ms |
| 修改后的初始化耗时（另计） | 未单独记录 | 136.917 ms |

这些是 `RimeRuntime.key` 的调用耗时，**不是屏幕帧率或完整“触摸到文字显示”延迟**。读音表加载被移到初始化阶段，初始化成本没有凭空消失。候选扩展本身在该样本中通常低于 1 ms，保留了原来的 150 项扩展读取和展开能力。

## iOS 18 额外发现与修复

原版真机采样记录完数值后，在测试对象释放时崩溃，栈包含 `swift::TaskLocal::StopLookupScope`、`swift_task_deinitOnExecutorImpl` 和 `RimeRuntime.__deallocating_deinit`。它与 [Swift 官方仓库 #88036](https://github.com/swiftlang/swift/issues/88036) 描述的旧系统 synthesized isolated deinit 问题吻合。

按该问题提供的方式给 `RimeRuntime` 增加显式空 `deinit`，引擎关闭仍在主线程 `close()` 中处理。修复后真机七个引擎/词典测试均正常结束，没有再发生原释放崩溃。原失败包保留为 `.build-artifacts/TypingLatencyBeforeDeviceUnlocked.xcresult`，没有将该次运行算作通过。
