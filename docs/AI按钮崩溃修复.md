# 完全访问已开启时，AI 按钮导致退回系统键盘

更新：2026-11-03。此记录修正此前“面板切换通过即代表 AI 功能通过”的验收缺口。

## 现场证据

用户反馈开启完全访问后，“帮你回 → 粘贴 TA 的话”和“超会说 → 优化”仍会导致键盘消失。检查本机该扩展的崩溃记录，确认有两种程序错误：

| 现象 | 崩溃栈 | 原因 |
| --- | --- | --- |
| 点击粘贴 / 优化后退回系统键盘 | `_UIApplicationAssertForExtensionType → UIAlertController.init → KeyboardViewController.generate`，`SIGABRT` | 扩展创建首次 AI 内容授权系统弹窗，触发 iOS 对键盘扩展的运行时限制 |
| 跳转主 App 失败后退出 | 同一系统断言，位于 `openMain` 回调 | 跳转失败的说明也使用了系统弹窗 |
| 收起 / 切换输入框时偶发退出 | `UUID._unconditionallyBridgeFromObjectiveC → textDidChange`，`SIGTRAP` | 宿主断开时 Objective-C 返回空标识，Swift 非可选 UUID 桥接崩溃 |

这些是程序错误，不是用户缺少完全访问权限。现场日志摘要只保留异常类别和函数名，不复制完整崩溃报告中的设备信息。

## 修复

- 移除键盘扩展中的全部 `UIAlertController`。内容授权、普通提示、语音指引和跳转失败说明改成键盘内部卡片；取消和同意都在原键盘区域完成。
- 通过公开 `documentIdentifier` Objective-C getter 的可空结果读取标识，避免非可选 UUID 桥接；AI 请求和结果写入都要求当前存在有效输入框标识。
- 输入框断开或更换时取消旧任务、清空旧结果状态，不将迟到结果写入其他输入框。
- 补查截图入口，发现模态选图取消后可能失去宿主键盘焦点。改为在扩展内部嵌入系统选图器，并提供自己的取消按钮；图片异步加载检查输入框、账号、模式与任务代次。

## 实测范围

在独立 iPhone 18 Pro / iOS 27.0 模拟器中安装实际 App 和键盘扩展，进入系统设置真实打开“允许完全访问”。测试没有替换 `hasFullAccess`，也没有在测试里绕过权限判断。

服务响应由仅在 Debug 编译的隔离 fixture 提供，实际执行以下链路：点击按钮、读取测试剪贴板、内容授权、构造 AI 请求、解析响应、渲染三条结果、写入真实宿主文本框。fixture 校验 HTTPS 目标、POST 请求及非空消息体；没有使用用户账号、模型 Key 或线上额度。

| 用例 | 检查内容 |
| --- | --- |
| 完全访问 + 帮你回 | 第一次点击显示键盘内授权卡片；取消可回原面板；同意后显示三条回复；连续选择会替换上一条且保留原有文字 |
| 完全访问 + 超会说 | 空草稿有提示；内部输入不写入宿主；优化后显示三条话术；连续选择和替换正常 |
| 输入框生命周期 | AI 操作后连续三次收起与重新打开键盘；空标识 / 未知代理对象不崩溃 |
| HTTP 503 | 显示服务错误及关闭入口，扩展仍在 |
| 超时 | 显示错误卡片，扩展仍在 |
| 没有模型 | 显示配置引导；无法自动打开主 App 时显示内部说明 |
| 其他入口 | 语音指引可关闭；系统选图可取消并恢复原键盘 |
| 普通键盘回归 | 九键上屏、候选清晰度、英文补全、空格、草稿隔离、符号、表情、数字与横屏 |

**本轮 8 项测试全部通过**（2 项空标识保护、5 项 AI 按钮流程、1 项普通键盘回归），Release 构建通过。最终通过状态、结果包和截图见 [AI 按钮回归结果](ai-button-results.json)。测试失败尝试也保留结果包，未当作通过。

真实服务商返回质量、真实账户订阅及收费链路仍需受控账号联调；本轮通过的是上述实际按钮链路与模拟服务响应，不冒称已调用线上模型。
